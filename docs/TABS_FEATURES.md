# 탭별 기능 명세 (Asset-Guard 대시보드)

> 지갑 로그인 후 좌측 탭으로 전환되는 각 화면의 기능을 정리합니다.
> 일반 사용자는 [대시보드] → [내 자산 목록] → [유휴 자산(전사)] 까지,
> 관리자(화이트리스트)는 여기에 [전사 대시보드], [관리자 렌탈 자산 관리],
> [인사 정보 관리]가 추가됩니다.

| 탭 | 접근 권한 | 핵심 용도 |
|---|---|---|
| 대시보드 | 전체 | 내 자산 통계 + 청구 달력 + 월간 리포팅(내 자산) |
| 전사 대시보드 | 관리자 | 전사 자산 통계 + 월간 리포팅(전체 자산) |
| 내가 관리하고 있는 자산목록 | 전체 | 내 담당 자산 조회·등록·이전 요청/수신 |
| 유휴 자산(전사) | 전체 | 회사 전체 유휴 자산 조회(공개) |
| 관리자 렌탈 자산 관리 | 관리자 | 전체 자산 인라인 수정 + 이전 요청 배치 승인/거절 |
| 인사 정보 관리 | 관리자 | 인사 프로필 관리(월간 리포팅 판단 기준) |

전체 화면 공통: **10초 주기 폴링 + 포커스/가시성 복귀 시 조용한 재조회**를 하며,
`applyDiff`로 이전 스냅샷과 비교해 실제 변경된 행만 5초간 하이라이트(플래시)합니다.

---

## 1. 대시보드 (overview)

### 1-1. 통계 카드 (내 자산 기준, `계약종료` 제외)

| 카드 | 의미 |
|---|---|
| 총 렌탈 자산 | 내가 담당(`managed_by = 내 지갑`)한 자산 수 |
| 정상사용 | 상태가 `정상사용`인 자산 수 |
| 유휴 | 상태가 `유휴`인 자산 수 |
| 이전 진행 | 내게 이전 요청이 온 인입 + 내가 보낸 진행 중 요청(수신자 미결의)수 |
| N월 렌탈비 합계 | 내 자산 중 `계약종료` 제외, 해당 월 렌탈료 합계 (원) |

### 1-2. 청구 달력 (BillingCalendar)

- 연 단위 달력 뷰로 월별 렌탈비 합계를 표시합니다(`buildYearPayments`).
- `계약종료` 자산은 청구 대상에서 제외됩니다.

### 1-3. 월간 리포팅 (MonthlyReport, scope=mine)

`GET /api/monthly-report?month=YYYY-MM&scope=mine` — 내가 관리하는 자산(계약종료 제외) 기준.
렌탈 자산의 사용자 이름(`user_name`)을 인사 프로필(`employee_profiles.user_name`)과 매칭해
**① 확인 필요 자산**과 **② 만기 도래 자산** 두 리스트를 만듭니다.

#### ① 확인 필요 자산 — 사유별 권장조치

`confirmRuleFor` 우선순위(낮을수록 우선)와 권장조치는 다음과 같습니다.

| # | 사유 (REASON_BADGE) | 판단 조건 | 권장조치 |
|---|---|---|---|
| 1 | 퇴직 | 인사상태 = 퇴직 | 기기 반납·이관 확인 |
| 2 | 퇴직(전근) 예정 | `departure_date` ∈ [조회월 1일, +3개월 말] | 기기 반납·이관 확인 |
| 3 | 신규 입사 | `hire_date` = 조회월 | 장비 지급 확인 |
| 4 | 휴직 / 출산휴가 / 육아휴직 | 인사상태 = 해당 상태 | 기기 보관·대체자 인수 확인 |
| 5 | 파견 근무 | 인사상태 = 파견 | 파견지 장비 이전·재배정 확인 |
| 6 | 자산-근무지 위치 상이 | 자산위치(카테고리) ≠ 근무위치 (둘 다 식별 가능 시) | 장비 이전·배정 확인 |
| 7 | 수습 / 기타 | 인사상태 = 수습 / 기타 | 사유 확인 |

- **위치 판정**: 자유 텍스트 자산위치를 카테고리(본사/지사/해외지사/재택)로 정규화해
  근무위치와 비교합니다. `자산위치`가 어떤 카테고리에도 매핑되지 않으면(미상)
  판정에서 제외됩니다. 지사-지사, 본사-본사 등 **일치하면 미표시**,
  근무위치=본사 + 자산=`B-XX지사` 같은 **불일치만 표시**합니다.
- 사유는 "자산-근무지 위치 상이"라는 범용 배지(violet)로 표시됩니다.
- 테이블 컬럼: 사유 · 관리번호 · 모델명 · 사용자 · 부문/팀 · 자산위치 · 인사상태 ·
  근무위치 · **입사일** · **퇴직(예정)일** · 권장조치
  - 퇴직(전근) 예정인 경우 퇴직(예정)일 컬럼에 **`N일 남음`**(10px neutral-500) 표기.
- 정렬: 관리번호 내림차순.

#### ② 만기 도래 자산 — 이분화된 권장조치

필터 조건: `rental_end_date` 존재 && 상태 ≠ `계약종료` &&
`rental_end_date <= 조회월의 +3개월 말일` (**과거 기한 경과 자산도 전부 포함**).

| 상황 | `days_left` | 권장조치 |
|---|---|---|
| 기한 지남 | `< 0` | **반납·연장 대책 필요 (기한 경과)** — 붉은 강조, "기간 경과" 배지 |
| 기한 이내(+3개월 이내) | `>= 0` | 재계약(연장)·반납 검토 — `D-N` 배지 |

- 정렬: 렌탈 종료일 오름차순(가장 급한 것이 상단).

> **우선순위 규칙 요약**: 퇴직 > 퇴직예정 > 신규입사 > 휴직류 > 파견 >
> 자산-근무지 위치 상이(위치 불일치) > 수습/기타.

## 2. 전사 대시보드 (corp) — 관리자 전용

- `GET /api/rental-assets?all=1` — **전체 자산(계약종료 포함)** 기준.
- 관리자용 통계 카드 5종(총/정상사용/유휴/이전 진행/당월 렌탈비)을 전사 기준으로 표시.
  - "이전 진행" = 진행 중인 **모든 이전 요청**(수신자 미결의).
- 청구 달력(계약종료 제외), 월간 리포팅을 **scope=all**(전체 자산)로 표시합니다.
- 10초 폴링/포커스 복귀 시 전사 데이터도 조용히 갱신됩니다.

## 3. 내가 관리하고 있는 자산목록 (my)

- **동시 표시**: 내 담당(`managed_by = 내 지갑`) 자산 + **내게 이전 요청이 온 인입 자산**.
  인입 자산은 목록에서 바로 인수 승인/거절 처리 가능.
- **정렬**: 이전 흐름에 관여된 자산(내가 보낸 진행 중 이전 / 내게 온 이전)을 **최상단** 배치
  (수신자가 이미 거절한 경우 제외).
- **자산 등록**(등록 모달): 카테고리·모델명·제조사·시리얼·사용자·부문/팀·자산위치·렌탈사·
  렌탈 시작/종료·렌탈료·청구 등을 입력.
  - **사용자 = 인사 프로필 select**(`/api/hr-people`): 등록된 인사 중에서 선택하고
    부문/팀은 프로필 값으로 자동 채움(수정 가능). 새 인원은 인사 정보 관리(관리자)에서 먼저 등록.
  - 서버에서도 `employee_profiles` 존재 검증(0016 FK). 미등록 인원이면 400 거부.
- **필터(AssetFilterBar)**: 상태·카테고리·부문/팀·장소·렌탈사 등 조건 조합 검색.
- **이전 요청 보내기**: 지갑 디렉토리(WalletDirectoryPicker)에서 수신자 지갑 선택 → `pending_to_wallet` 설정.
- **인입 행**: "내게 이전 요청" 배지 + [인수 승인]/[인수 거절] 버튼.
  - 승인 → `pending_receiver_approved_at` 기록 → 이후 관리자 최종 승인 대기.
- **진행 상태 배지** (상태 열과 연동):
  - 내가 보냄·수신자 미결의 → `↦ 주소`(amber) + `수신자 승인 대기`(blue) + [취소] — 상태 열 = 상태 배지
  - 내가 보냄·수신자 승인 → `↦ 주소 승인 완료`(emerald) — 상태 열 = **`관리자 승인 대기`**(amber)
  - 내가 보냄·수신자 거절 → `↦ 주소 인수 거절`(red) — 상태 열 = 상태 배지
  - 인입·미결의 → `내게 이전 요청`(blue) + [인수 승인]/[인수 거절]
  - 인입·승인 → `인수 승인 완료`(amber) — 상태 열 = `관리자 승인 대기` / 인입·거절 → `인수 거절됨`(red)
  - 계약종료 → `—`
- **이전 요청 취소**: 확정 전까지 DELETE로 요청 초기화(거절 흔적 없음).
- 각 행에서 **이관 그래프**(lineage) 링크를 열어 온체인 서명 포함 전 이력을 확인.

> 이전 요청 흐름 요약: 앨리스 요청 → 밥 인수 승인/거절 → 찰리(관리자) 최종 승인 시
> 온체인 서명 후 소유권 이전. (상세는 `BLOCKCHAIN_DESIGN.md`)

## 4. 유휴 자산(전사) (idle)

- `GET /api/rental-assets?idle=1` — **상태 = 유휴**인 회사 전체 자산을
  로그인한 모든 사용자가 조회(내 담당 여부와 무관, 전사 공개).
- AssetFilterBar 필터 지원(상태 고정 유휴이므로 카테고리·부문 등으로 세분).
- 컬럼: 관리번호 · 카테고리 · 모델명(+SN) · 제조사 · 사용자 · 부문/팀 · 자산위치 · 렌탈사 ·
  청구 · 렌탈료 · 렌탈 시작일 · 렌탈 종료일 · **상태(유휴만)**.
- 재구성이 잦은 전사 리스트 특성상 diff 플래시 없이 10초 폴링으로 조용히 갱신합니다.
- 목적: 유휴 장비 재배치(인수 배정) 검토의 전사 가시성 제공.

## 5. 관리자 렌탈 자산 관리 (admin) — 관리자 전용

- `GET /api/rental-assets?all=1` — 전체 자산(계약종료 포함)을 관리자 전용 테이블로 표시.
- **인라인 수정** (PATCH, 관리자 전용): 카테고리(select) · 사용자(인사 select) · 부문/팀 ·
  자산위치 · 렌탈료 · 렌탈 시작/종료일 · 상태 — 셀에서 바로 편집·저장.
  - **편집 불가/열 없음**: 모델명·렌탈사는 읽기 전용, 시리얼·제조사·청구는 열 자체가 없음.
- **인수인계(이전) 관리**:
  - 각 행의 이전 요청 상태를 배지로 표시: `수신자 승인 대기 → 주소`(amber) / `수신자 승인 → 주소`(emerald) /
    `수신자 인수 거절 → 주소`(red) + 요청시각(10px). 진행 요청이 없으면 `—`.
  - **승인/거절 실행**: 행 단위 버튼 없음 — 체크박스 선택(진행 중이면서 수신자 미거절·관리자 미승인 항목만 활성)
    후 배치 바의 **[선택 M건 승인/거절]** 로 처리.
  - **일괄 승인**: `approve-batch`로 한 번에 처리. 승인은 **수신자 승인 완료 + `정상사용`** 항목만 적용
    (그 외는 배치 응답에서 `제외`). 온체인 배치는 트랜잭션 크기 제한에 맞춰 **최대 6건** 단위로 묶어 실행하며,
    배치 실패 시 개별 폴백 후 나머지도 처리해 "한 건이 문제여도 전체 중단 없음"을 보장. 일괄 거절은 모든 진행 요청에 적용.
- **정렬**: 진행 중 이전(수신자 승인 대기 → 수신자 승인) 자산이 목록 **최상단**에 옵니다.
- **컬럼 폭**: 넓은 필드(사용자·부문/팀·자산위치 등) 가독성을 위해 테이블
  `min-w 2000px` + 열별 최소폭을 지정해 가로 스크롤로 전체 정보를 노출합니다.
- 이관 그래프(라인리지)와 이관 기록(Explorer 링크)으로 확정된 이전의 온체인 증거를 확인할 수 있습니다.

## 6. 인사 정보 관리 (hr) — 관리자 전용

> **현재 상태**: 더미데이터용으로 동작하지만 **추후 ERP 연동을 가정**한 설계입니다.
> 지갑은 프로필 식별자로 쓰지 않으며, 프로필 PK는 **`user_name`**입니다
> (렌탈리스트에서 파생된 사용자 + 관리자가 임의 추가한 사용자).
> 0016 부터 자산의 `user_name`은 이 프로필을 **외래 키로 참조**합니다 (프로필 선행 등록).

### 6-1. 데이터 원천 (`employee_profiles`)

`GET /api/employees` 조회 시 렌탈 자산에 등장한 사용자 이름을 기준으로 목록이 구성됩니다.
프로필 필드:

| 필드 | 의미 |
|---|---|
| `user_name` | 프로필 키 (PK) |
| `employment_status` | 인사상태: 재직 / 수습 / 휴직 / 출산휴가 / 육아휴직 / 파견 / 퇴직 / 기타 |
| `work_location` | 근무위치: 본사 / 지사 / 재택 / 해외지사 / 출장중 |
| `division` | 부문 — select 목록(A부문/B부문/C부문, 0015). 렌탈 자산 파생 값 보완 |
| `department` | 팀 — select 목록(AAAA팀~FFFF팀, 0015). 렌탈 자산 파생 값 보완 |
| `job_title` | 직급 |
| `hire_date` | 입사일 |
| `departure_date` | 퇴직(전근) 예정일 |
| `note` | 비고 |
| 출처 | 목록 렌탈리스트 사용자(렌탈 자산에서 파생) / 임의 입력 |

> `division`/`department`는 **선택 목록(select)** 으로 관리합니다(0015 마이그레이션에서 추가).
> 렌탈 자산 씨드 기반 기본 목록 + 저장된 값 중 목록 밖 값(렌탈 자산 유래)을 보완 옵션으로 노출합니다.
> `GET`은 프로필 저장 값 우선, 저장 값이 비어 있으면 자산 파생 값으로 표시합니다(기존 표시 유지).
>
> **FK (0016)**: `rental_assets.user_name → employee_profiles.user_name`. 자산 등록 시 프로필 존재를
> 검증해 **미등록 인원은 배정 불가**하며, "렌탈리스트 인수 대기" 자동 제안은 0016 이전에 등록된
> 레거시 자산 이름에만 발생합니다.

### 6-2. 화면 기능

- **검색**: 이름·부문·팀 기준으로 필터링.
- **신규 등록**: 프로필이 없는 사용자 이름을 추가해 등록(임의 입력, PK는 이름).
- **인라인 편집·저장**: 부문/팀(select) · 인사상태/근무위치(select) · 직급/비고(input) · 입사일/퇴직(예정)일(date)를 수정 후
  `POST /api/employees`로 저장.
- **권한**: 관리자 화이트리스트(`x-admin-wallet`) 전용.

### 6-3. 월간 리포팅과의 연계 (핵심 용도)

대시보드 월간 리포팅의 ① "확인 필요 자산" 판단(퇴직/퇴직예정/신규입사/휴직/파견/
위치 상이/수습·기타)이 **이 인사 프로필을 기준**으로 계산됩니다.
따라서 인사 정보를 갱신하면 다음 달 리포팅의 권장조치가 즉시 달라집니다.

### 6-4. ERP 연동 가정 (향후)

- **HI/인사 시스템을 단일 진실원천(Source of Truth)** 으로 두고
  근무지·직급·입퇴사일·휴직 상태 등을 임계치만큼 검증·동기화합니다.
- ERP에서 퇴직/휴직/발령 이벤트가 발생하면 장부에 즉시 반영되어
  월간 리포팅이 "자산 대비 인사 이벤트"를 자동 감지하도록 설계를 열어 둡니다.
- 현재는 시드·더미 입력으로 동작하며, 연동 시 수동 입력 없이도
  확인 필요 자산 목록이 실시간으로 갱신됩니다.
